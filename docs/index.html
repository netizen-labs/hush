Why hush

Small enough to read. Serious enough to trust.

📦

Zero dependencies

Pure standard-library Python — a few hundred readable lines. No C extensions, no transitive tree, no supply chain to trust.

🎯

Two detectors

Curated regex rules for known secret shapes, plus a Shannon-entropy detector for the random blobs no pattern knows. Deduplicated, never doubled.

🌿

Git-native

Scan the index as a pre-commit gate, or sweep the whole history to find secrets that were "removed" but still live in old commits.

📋

Reviewable baselines

Accept known findings into a baseline that stores fingerprints and redacted context — never a raw secret. Only new leaks get reported.

🔒

Safe by default

Secrets are redacted in every report unless you explicitly ask to reveal them. Nothing leaks through the tool meant to stop leaks.

⚙️

CI-ready

Clean exit codes (0/1/2), JSON output, a pre-commit hook, and a GitHub Actions workflow. Drop it into any pipeline in minutes.

Get started

Three commands to a safer repo.

# install
pip install hush-scan

# scan the current directory
hush scan

# gate every commit (reads the git index)
hush scan --staged

# audit history for secrets that were "removed"
hush scan --history

Or wire it into pre-commit:

# .pre-commit-config.yaml
repos:
  - repo: https://github.com/netizen-labs/hush
    rev: v0.1.0
    hooks:
      - id: hush

🤫 hush is a safety net, not a vault. A clean scan is not a guarantee — and if a secret has ever been committed, rotate it. Deletion doesn't un-leak it.
